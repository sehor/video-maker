目标：在保持行为和账本不变量的前提下，提高模块内聚性、显式化依赖、增强类型约束，并控制阻塞 IO 与大对象内存开销。

## 1. 原则和边界

- P1 修复以[计划一](01_业务逻辑修复计划.md)为准，不能等待大规模重构才修复。这里不重复实现 F1–F8。
- 保留 PostgreSQL 业务真相、事务边界、稳定幂等键和 Provider/Storage Contract。行为变更必须回到对应业务 Issue 说明。
- 不以文件越短、类越多、目录越深作为质量目标；不建设通用插件系统、通用 Repository 框架或新的调度平台。
- 最终目录和新类名是实现建议，实施 Issue 以实际调用链为准。一个任务超过一个会话时按模块切片；禁止同时修改同一组核心服务。
- 任务编号是规划 ID，实施时各建独立 Issue，验证并本地提交。发布或数据迁移前保留可回滚版本和明确兼容性说明。

## 2. 目标职责

```text
HTTP 路由：认证上下文、请求校验、响应映射
    ↓
应用服务：一个业务用例、事务入口、跨模块协调
    ↓
领域操作：账本、状态迁移、输入快照、路由规则
    ↓
基础设施：SQLAlchemy session 工厂、Provider、Storage、WorkflowStarter

应用启动层：构建上述依赖，并管理 runner / dispatcher 生命周期
```

依赖方向向下；基础设施不反向导入 HTTP 路由。账本和状态机操作可共用调用者传入的事务，但不能自行偷偷提交。Provider 网络请求及对象下载/发布不得长期占有业务数据库事务。

## 4. 具体任务

### CQ-01：建立可比较的结构与行为基线

- **范围**：只读检查 `public_api.py`、`provider_execution*.py`、`provider_completion.py`、`ledger.py`、`main.py` 和关键测试；输出一份简洁基线记录。
- 绘制 API→事务→Outbox→执行→完成→账本调用链，列出 session 所有权、commit 位置、幂等键、外部副作用与可注入依赖。
- 记录已有测试覆盖和缺口。优先补真正缺失的行为测试，不复制当前实现细节、不批量快照所有 JSON。
- **验收**：明确每个待拆模块的职责、输入输出与禁止反向依赖；后续结构比较以此为准。已有 Graphify 图过期时只作导航，不能作为当前结构证据。

### CQ-02：收缩 HTTP 层职责

- **切片**：① 启动依赖组装；② Project/Asset 用例；③ Quote/Wallet 用例；④ Generation/Batch/Cancel 用例。每个切片独立 Issue 和验证。
- 从 `public_api.py` 移出 Storage/Provider/dispatcher 工厂及业务组装，交给启动层与应用服务。按业务域分路由，但不只做机械文件切分。
- `api.py` 的兼容导出改为明确名单；生产代码不为测试 monkeypatch 反向导入兼容 facade。测试通过构造参数或依赖覆盖注入。
- **验收**：公开 URL、状态码、响应模型和鉴权规则不变；路由不直接组装账本分录、Attempt/Outbox 对象；事务仍覆盖应原子完成的业务；不存在“基础设施→HTTP 路由”的导入。
- **验证**：公共 API 契约、权限、Generation/Batch 原子性、取消与 Outbox 测试；导出 OpenAPI 差异必须为空或仅为预先说明的文档变化。

### CQ-03：用显式依赖替代六重 Service 继承

- **切片**：① 执行上下文及协作接口；② submission/polling/callback；③ completion/settlement；④ 删除兼容基类。每步保持调用方可运行。
- 定义小而明确的协作者：上下文加载、提交握手、轮询预算、事件接收、结果完成。构造时注入 session 工厂、Storage、Provider/Route registry、时钟和媒体接收器。
- 一个协作者不能依赖另一个基类在运行时“碰巧存在”的私有方法；不要求所有模块都引入 Protocol，只对实际替换边界使用。
- Completion 保留单一终态/发布/结算入口；内嵌 Mock 和远端产物差异明确隔离，真实 Provider 不能通过内嵌输出绕过必需的元数据、大小和 SHA-256 一致性校验。统一表示 Provider 声明与校验结果，不能把声明值标记为“已实测”或把 VALID 解释为可播放证明。
- **验收**：核心协作者可独立构造测试；依赖均由参数体现；构造无网络请求；terminal transaction 仍统一；无重复结算、返还或输出发布。
- **验证**：submit unknown、旧 Attempt 通知、webhook/poll 竞争、取消与成功竞争、缺失/非法元数据、对象大小/哈希不符、重复完成及重放回归。模拟与真实适配契约分开记录。

### CQ-04：约束前端请求契约与错误模型

- **范围**：`useApi.ts`、`types/domain.ts`、API Client 封装和页面调用方；按封装与页面迁移拆 Issue。
- 保留已生成的响应类型，让 method/path/body/response 关联到 OpenAPI `paths`；避免仅靠调用者填写 `request<T>` 断言类型正确。
- 统一暴露错误 code、message、request_id、HTTP status 和“结果未知”信息，供 BL-03/08 的恢复策略使用；UI 不泄露内部供应商细节。
- **验收**：错误路径、方法或请求字段在类型检查时失败；合法请求可推导响应；FormData、204、下载保持行为；已有稳定 operation key 不被封装重写；所有业务页面迁移后移除宽泛兜底。
- **验证**：类型级错误样例、API 封装单测、前端 lint/typecheck、已有与新增 E2E。运行真实生成客户端 check，不能手工维护第二套 DTO。

### CQ-05：将剩余数据库与对象 IO 阻塞移出事件循环

- **范围**：执行服务、对象接收、上传/清理入口及生命周期处理，优先真实路线必经路径。媒体进程超时、进程树清理与解码并发控制已退出本任务。
- 先测量慢 DB、对象下载/发布、SHA-256 计算和文件传输时的事件循环延迟，再划分同步事务块与外部 IO 块；优先复用现有同步数据库模型和受控线程执行，是否采用异步驱动另立决策。轻量元数据判断不因本计划而被强制搬到线程池。
- 不把现有 SQLAlchemy Session 直接跨线程传递；每个执行上下文创建并关闭自身 session。设置并发边界，避免无限制 `to_thread`。
- **验收**：通过 fake 慢 DB/存储注入 2 秒阻塞期间，独立心跳/轻量请求仍持续执行；新建的确定性测试目标为最大心跳间隔小于 500ms，测试机器负载与方法一并记录。取消、超时、shutdown 能关闭连接和文件句柄，并按正确生命周期清理本次临时对象，不启动媒体子进程。
- **验证**：事件循环回归测试、并发上限测试、取消/超时测试和本地端到端；真实环境的 SLA 由 DL-02/05 采样决定，不能用此单测代替压测。

### CQ-06：实现流式存储与受控内存

- **范围**：Storage 协议实现、Artifact Receiver、共享契约测试和一个可重复运行的基准脚本。
- 避免 BinaryIO 经 `list[bytes]` 加 `join` 形成双份大对象；分块复制并增量计算 SHA-256，超限立即终止，失败清理仅针对本次写入。
- Local 与远端适配器保持相同不可覆盖、claim、大小和哈希语义；不要为优化偷偷放宽安全校验。
- **验收**：至少比较 64MiB 和 512MiB 的惰性生成流，记录相对空载峰值内存；目标是数据增大时进程额外内存保持有界，不随输入大小线性增长。初始工作缓冲预算为 64MiB，超出须有测量与明确调整记录。并发数按 CQ-05 限制。
- **验证**：超限、读取中断、目标写入失败、同 claim 重放、哈希一致性；回归 BL-01/05，证明优化不引入误删或遗留文件。

### CQ-07：建立持续可执行的质量门禁

- 依据 CQ-01 检查依赖方向、事务责任与可测试性，不设置任意“每文件不得超过多少行”的门槛。
- 扩大 Ruff 范围前先核对历史迁移治理：不为整理格式修改已发布迁移逻辑；对历史格式债务记录明确例外，新增迁移须通过检查。
- 关键边界补导入约束或轻量静态验证，避免通过长篇约定替代实际检查。CI 不因需要网络/凭据而悄悄跳过必需层。
- 保留自动测试对 FFmpeg/ffprobe 的启动拦截；新增元数据、Storage、Provider 或 POC 测试均使用固定样本/声明与 fake，不现场编码或完整解码。不得为了让旧测试通过重新引入媒体二进制依赖。
- **验收**：结构基线对比完成；全部必需测试和静态检查通过；远程 CI 结果单独记录；无为迁就重构而削弱幂等、金额、权限或恢复测试的改动。

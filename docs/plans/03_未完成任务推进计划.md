## 本次验收边界更新

以 `0778da9` 为新基线：控制面和 POC 接收均只检查 Provider 声明的时长、尺寸、画幅、帧率、编码/媒体类型，以及对象大小和 SHA-256 一致性，不启动 FFmpeg/ffprobe、不完整解码、不由控制面生成预览图。第三方生成 Worker 的编码职责不受此调整影响。

DL-02、DL-05、DL-06 的放行标准据此更新；真实 GPU POC、版本追溯、成本、对象传输、故障恢复和人工质量/一致性 Benchmark 仍须完成。自动测试不启动媒体进程，浏览器 E2E 继续使用固定样本；不得把元数据检查通过或本次 11 条数据库回归通过等同于真实路线/可播放性总验收。

### DL-01：整理离线准备，先定义通过标准

- 核对现有 Worker、manifest、请求/响应 schema、POC 脚本和发布模板；将“有代码”“离线通过”“真实通过”分开列证据。
- 固定 5 秒、720p、16:9/9:16、参考图输入，准备有权使用的测试素材、预期媒体规格和失败样本。
- 在执行前记录成功率、p95 时延、单位成功输出秒成本、质量和一致性的验收阈值、样本量及预算停止条件；阈值不能在看到结果后无说明地下调。
- **验收**：#14–#16 每条剩余验收项有负责人/执行入口/证据位置；dry-run 不启动 GPU；没有伪造 digest、模型哈希或 Benchmark 数据。
- **范围**：`workers/runpod-comfyui/`、`workflows/manifests/`、`scripts/run_worker_comfyui_poc.py`、`scripts/release_worker.py` 及对应测试。

### DL-02：执行真实 POC，决定路线能否继续

- 复用现有独立 POC 脚本，使用固定 fixture 和受控测试传输；此处先验证 Worker 推理，不把它当成完整 Web→Storage→Hatchet 链路。
- 收集真实 GPU、镜像/模型/workflow 标识、横竖屏输出、冷启动、运行时间、实际计费及失败记录。结果接收验证必需元数据及对象大小/SHA-256 一致性；缺失或非法声明、规格不符、空对象或传输不一致必须拒绝。不得追加本机完整解码作为门槛。
- 按预先约定的停止条件终止失败或超预算实验，执行资源清理并核对账单。
- **验收**：得到可复查的继续/拒绝结论；失败仍保留原始证据。未执行则保持 CONDITIONAL，不能以模板或模拟日志代替。
- **交付**：#14 的 POC 报告、原始指标、对象位置和清理记录。费用授权不足时只完成 DL-01。

### DL-03：接通真实私有对象存储

- **切片**：① 根据环境确定适配器及契约；② 实现真实读写/签名或 claim 交换；③ Worker 端接入及恢复测试。每片独立 Issue。
- 复用 ObjectStorage 边界，明确短期 claim 如何在 Worker 侧转换成受限传输；禁止把本地路径当作远端地址，禁止把签名密钥交给 Worker。
- 处理队列等待超过 claim TTL 的情况：刷新/重新交换必须绑定原 Job/Attempt/对象，保持稳定提交幂等语义；不能无条件延长凭据有效期来绕过。
- **验收**：真实后端通过共享契约，过期/越权/路径穿越/重放被正确处理；大文件有大小限制；传输中断可恢复；清理覆盖源对象和最终对象。
- **范围**：Storage 适配器、受控 claim 交换接口（如需要）、Worker 传输层及共享测试。供应商选择写 ADR，不提前假设一定使用 R2。

### DL-04：关闭 Worker 发布证据缺口

- 实际构建发布候选并在 registry 核实不可变 digest；生成 SBOM、许可证通知、模型/节点登记和 workflow 哈希，绑定真实 POC 与 smoke 证据。
- 建立当前版本与回滚版本的发布记录；没有真实证据时保持 `BLOCKED_UNVALIDATED`，不修改模板字段让门禁假通过。
- **验收**：发布脚本拒绝缺失或不一致证据；候选镜像可启动并完成固定 smoke；回滚目标可用；版本追溯贯穿 Worker 输出与 Attempt。
- **范围**：现有 release 脚本、Worker 镜像配置、release 记录、许可证台账；更新 #15。

### DL-05：真实 Hatchet、RunPod 和路由联调

- **切片**：① 真实 Hatchet Windows Worker 的连接/重启恢复；② Adapter 注册与配置校验；③ 私有传输/回调/轮询/取消集成。每片独立 Issue。
- 先在隔离 staging 注册已通过 POC/发布门禁的候选路线，仅测试身份允许接单；默认生产配置仍关闭。环境变量不能绕过发布记录和环境校验。
- 使用真实 `submit/poll/webhook/cancel`、成本读取与媒体接收链；Project 绑定和 kill switch 复用 BL-04B 的数据库真相，多 API/Worker 进程不各自维护冲突开关。
- **验收**：UI 选择素材→Quote→冻结→真实任务→元数据与对象完整性校验→唯一输出→结算可追踪；服务重启可恢复；响应未知不重复 submit；取消不提前返还；元数据缺失/非法、对象大小/哈希不符等真实错误仍进入统一失败路径。
- **证据**：请求、Job、Attempt、Provider Job、Worker、对象和账本关联；敏感凭据/claim 不进日志。记录运行时延供后续 Benchmark 比较。

### DL-06：Benchmark 和阶段三总验收

- **切片**：① 固定数据集 Benchmark；② 真实故障/恢复及成本对账；③ 汇总 #14–#16 验收与发布候选决定。
- 数据集覆盖阶段三要求的场景，每组至少重复三次；若 DL-01 的样本量更高，按更高要求。记录成功率、OOM、队列/冷启动/运行 p50/p95、全部重试成本、每成功输出秒成本和人工一致性评分。
- 故障覆盖 submit 断连、重复/乱序/迟到回调、poll/webhook 竞争、Worker 重启、Storage 不可写、取消与成功竞争、Outbox 重放及对账差异。
- **验收**：达到事前阈值；账本不变量成立；输出有真实版本、Provider 元数据及对象完整性证据；失败及超预算情况有停单/恢复方案。控制面缩略图/预览图生成不再是阶段三缺口，不为此新增编码/解码任务。人工质量和一致性评估独立留证，不把其结论混同于同步结果校验。
- 对只靠解码才能发现、但声明和字节一致性均合法的内容损坏，不再承诺在同步发布/结算前检测到；元数据验收与真实观看质量分别统计和报告。不能用 SHA-256 一致性证明 Provider 声明与文件实际媒体属性完全相符。
- 本机回归、真实服务联调、GPU Benchmark、远程 CI 分开签收。只有该层证据充分才更新阶段三状态和原 Issue；不靠已有模拟报告关闭真实验收项。

### DL-07A / DL-07B：补齐面向用户的产品闭环

- DL-07A 补 `/pricing`、`/wallet`、`/ledger`、`/account`；余额及冻结状态来自 API，流水稳定分页，错误可恢复。生产隐藏测试发放入口，套餐只显示真实可售质量档和规格。
- DL-07B 补 Batch 创建、报价确认及详情：提交前展示镜头、总秒数/费用、余额，确认后整体冻结，各 Job 独立显示结果，仅下载成功输出。单任务也展示报价再确认。
- **验收**：普通用户不见模型、Provider、workflow 等内部参数；余额不足和报价失效可处理；刷新与恢复不会重复提交；绑定素材确实进入生成输入。
- **规格边界**：私测默认保持当前 `variant_count=1`。若产品要求多 variant，必须先建独立领域 Issue，完成 Quote、Job 拆分、冻结/结算和唯一性契约，不能只开放 UI 数值；阶段四文档同步记录最终选择。
- **验证**：真实 API 契约、前端单测和隔离 E2E；所有权、分页、报价变化和部分失败都要有用例。

### DL-08A：订单与 Checkout

- **切片**：① 商品/账期/权益契约和兼容迁移；② 订单与 Checkout API；③ 支付页面。先锁定规则再接供应商。
- 订单固定商品、金额、币种、用户、环境和价格版本，具备稳定商户订单号与幂等创建。定义订单过期、支付晚到、重复支付和不匹配事件的处理。
- 有效期设计必须能追踪每批发放额度及消费/冻结归属，为 DL-08D 提供依据，不能只给汇总余额加一个到期时间。
- **验收**：价格变动不改历史订单；浏览器 success 页面只能查询状态，不能发放额度；供应商身份和环境不串用。

### DL-08B：支付完成与发放

- 验证 webhook 签名及金额/币种/商品/环境，事件与订单均有唯一约束。订单 paid 与账本 grant 在同一数据库事务内完成；外部副作用使用 Outbox。
- **验收**：重复、乱序、延迟回调及事务中断不会重复发放；跨用户/跨环境事件不能入账；无法关联的事件保留诊断且不擅自建单。
- **验证**：真实 PostgreSQL 并发回归及支付 sandbox；sandbox 和真实小额验证分别留证。真实扣款需另行明确额度与执行授权。

### DL-08C：退款与撤销

- 明确未使用、部分使用、已冻结额度的退款规则，记录退款请求/结果及幂等键；外部退款与本地状态通过可恢复流程衔接。
- 通过反向分录记录变动，不删除旧交易。异常和拒付进入人工处理，不能静默把用户余额改为负值或伪造成功。
- **验收**：重复退款通知、外部已退款本地未记账、退款与生成并发均可恢复，金额/秒数归属可解释；sandbox 场景全部有测试。

### DL-08D：额度有效期

- 按 DL-08A 的额度批次和分配规则实现到期处理；明确冻结中的额度到期、任务失败返还、退款与到期竞争时的结果。
- 到期只通过幂等账本交易转入适当平台账户；已过期额度不得因任务失败返还而重新变成可消费额度。
- **验收**：时钟跨界、重复调度、并发提交/结算/返还/退款不会超扣或重复过期；流水能说明来源，余额投影与分录一致。
- **验证**：Fake Clock + 真 PostgreSQL 并发测试，避免等待真实时间；保留人工恢复流程。

### DL-09A / DL-09B：最小策略和人工复核

- DL-09A 定义平台自己的 ALLOW/REVIEW_REQUIRED/BLOCK 规则与版本，绑定不可变输入快照；BLOCK 不冻结/扣费，待审任务不提交 Provider，审核结果有审计。
- DL-09B 在最终发布/结算前接入最小结果策略，定义待审、放行、拒绝、取消和异常恢复语义；审核中的结果不可公开下载。
- **验收**：重复审核和乱序事件不重复结算或返还；策略拒绝不当作可重试基础设施错误；用户看到明确结果但不泄露内部策略详情。
- **范围**：策略应用服务、必要状态/迁移、审核 API/UI 和测试。数据/状态机变化先补契约，不建设通用 Agent 或工作流编辑器。

### DL-10A / DL-10B：补齐 Admin

- DL-10A 扩展现有诊断/死信能力：完整 Job/Attempt/Event/版本查询、持久路线启停、角色权限、审计查询。多进程下停单必须一致，在途 Job 仍能终结。
- DL-10B 增加受控重试、异常冻结释放与双分录余额调整；操作填写理由，界面二次确认，API 验权、幂等和审计独立生效。
- **验收**：不能直接改余额、重开已结算 Job 或覆盖历史输出；重放同一管理员操作无重复副作用；非管理员调用被拒绝。审核模块的处理界面可复用此权限边界。

### DL-11A：可重复运行的对账

- **切片**：① 分录↔余额投影↔Job；② Attempt↔供应商成本；③ order/webhook/refund↔ledger。先只读报告，修复动作使用现有受控流程。
- **验收**：注入重复、漏记、错误关联及成本缺失样本能发现差异；重跑不污染账本；官方成本与 ESTIMATE 分开；报表不把失败重试成本遗漏。
- 差异进入运维待处理队列，人工确认后形成修复 Issue；不默认发送外部消息或自动改写历史。

### DL-11B：指标、告警与 Runbook

- 覆盖成功率、排队/总时延、错误、Outbox/死信、卡住任务、Hatchet Worker、Storage、重复回调、账本差异和单位成功秒成本。
- 统一关联 request/job/attempt/order，Prometheus 标签不放用户/任务 ID。告警阈值取自已验收容量和成本边界，接收者明确。
- **验收**：实际触发并恢复一组故障告警；有去重、恢复通知和处置步骤；日志/指标不含密钥或完整 claim。

### DL-12：隔离部署与恢复能力

- **切片**：① staging/production 配置和权限隔离；② 数据库/对象备份与恢复演练；③ CI/CD、回滚及容量检查。Docker/Compose 操作前遵守现有维护预检与资源复用规则。
- 禁止 production 使用 local backend；各环境数据库、Auth、对象空间、支付、RunPod、callback 和告警分离。staging 先应用迁移，使用 expand/migrate/contract 管理不兼容变化。
- **验收**：从备份恢复到隔离环境，并验证账本、活跃任务和对象一致性；记录实际 RPO/RTO，与事前目标比较；回滚不降级破坏不可逆数据。
- 远程 CI 必须实际运行并留证。备份文件存在、`readyz` 返回 200、本机测试通过都不能独自代替恢复/发布验收。

### DL-13：邀请私测总验收

- 完成用户旅程：注册→选择套餐→测试支付→额度到账→素材/镜头/Batch→Quote 确认→真实生成→播放下载→流水核对→退款/到期处理。
- 演练 Route 停单、Worker 重启、存储故障、延迟/重复支付回调、数据库恢复和 callback secret 轮换。
- 逐项复核阶段四验收清单、商用许可/通知和隐私/用户条款；未决项列为阻断项，不能用“基本完成”勾选通过。
- **验收**：无未解决 P1；所有关键财务/所有权/恢复用例通过；服务质量与成本符合事前门槛；容量、邀请范围、回滚负责人明确。上线决定与执行记录单独留档。

## 5. 阶段五的推进边界

在 `0778da9` 的元数据验收基础上，按用户取舍进一步取消媒体哈希与声明大小一致性检查：控制面和 POC 结果接收只验证 Provider 声明的时长、尺寸、画幅、帧率、编码/媒体类型，以及对象存在、非空和大小上限；不启动 FFmpeg/ffprobe，不做完整解码。`VALID` 表示这些检查通过，不代表已经证明视频可播放。

## 3. 具体任务

### BL-01：保护重复写入时的原文件

- **范围**：`apps/api/app/storage.py`、`apps/api/tests/test_storage_contract.py`。
- 区分创建失败和本次新文件写入失败；只有本次创建的文件可被失败清理删除。保留原有冲突错误码，不把重复写入静默当作覆盖。
- **验收**：同 claim 顺序重复写、两个写入者竞争、流读取失败、磁盘写入失败均不删除先前已提交对象；冲突后原内容和大小不变；新写失败无半成品。
- **验证**：扩展 Local、Fake Remote、Remote 适配器共享契约测试；至少有一次真实 LocalObjectStorage 并发写入回归。
- **边界**：流式存储性能改造由 CQ-06 负责，本任务先完成数据保护。

### BL-02A：定义并存储不可变输入快照

- **范围**：`models.py`、新增 Alembic 迁移、`schemas.py`（如公开恢复需要）、迁移/数据库约束测试、核心契约文档。
- 快照至少含版本、prompt、明确的参考素材 ID/不可覆盖对象键、参考角色、必要生成参数。计价快照与执行快照分别表达职责。
- 设计新 Job 的快照必填规则及不可变性，保留历史终态数据的真实缺失状态。
- **验收**：空库及现有数据升级成功；旧终态记录可读取；不能把“当前 Shot 内容”伪装成历史提交输入；新规则启用后的 Job 不能缺快照。
- **发布方案**：新增兼容字段后，接入步骤采用暂停新接单、排空旧活动任务再切换的顺序。无法排空的任务列入人工处置清单，不自动替换其原意图或直接更改余额。
- **验证**：迁移与约束测试；审查回填脚本、回滚限制和活动任务检测查询。破坏性升级不得作为默认路径。

### BL-02B：让执行链只读取已接受输入

- **范围**：`public_api.py` 的 Generation/Batch 创建、输入快照服务、`provider_execution_context.py`、相关执行测试。
- 在创建 Job、冻结秒数及写 Outbox 的同一事务中保存快照。所有 Attempt、轮询、回调恢复和重试读取同一快照。
- UI 对 Shot 的修改只影响之后新建的 Job；解绑素材不破坏已接受的 Job。生成输入选择必须明确参考角色与数量，不能依靠最早创建的一条引用猜测用户意图。
- **验收**：提交后改 prompt、换图、解绑、重启、重试，原 Job 输入均不变化；后续新 Job 使用新内容；Batch 每项均保留独立快照；并发编辑与提交只有完整的旧版本或新版本。
- **验证**：把审查的两条输入探针转为正式数据库回归；增加并发编辑/提交和重试测试，断言 Provider 实际收到的 request/claim。
- **边界**：不扩展新的参考图产品能力；只明确当前固定路线支持的输入契约。

### BL-03：修复响应不明时的重复生成

- **范围**：镜头生成页、`useApi.ts`、一个操作状态模块及前端/E2E 测试；如缺恢复接口，先拆接口子 Issue。
- 一次用户意图对应稳定 operation ID、Quote 和生成 Idempotency-Key；请求结果不明时保留原 payload/键并恢复原操作。明确“恢复原请求”和“重新生成”的用户动作。
- 状态按登录用户和镜头隔离；持久化操作元数据，不保存 access token。定义刷新后、退出登录、Quote 过期、幂等结果保留期结束时的恢复规则。
- **验收**：服务端已接受但响应丢失、连续点击、页面刷新再恢复，最终仅一个 Job、一次冻结/结算；用户明确新建生成时才产生新任务。不能用自动新 Quote 来掩盖结果未知。
- **验证**：前端单测执行真实页面操作逻辑；E2E 在服务端接受后丢弃首个响应，断言 API/数据库仅一个 Job。覆盖稳定错误和临时错误的不同处理。

### BL-04A：定义项目级路线绑定

- **范围**：项目/路线数据模型、兼容迁移、契约文档及迁移测试。
- 采用“首次接单时暂定、首次成功后固化”的两步绑定方案：在成功前也保持同项目并发任务使用一致路线，兼容阶段五首次成功绑定的规则。没有成功前的重选也必须是明确、有审计的动作。
- 路线版本不可变，启停状态独立存储；已有项目数据按历史输出核对。若历史存在多路线，标记需处理，不自动声称已有一致性。
- **验收**：模型可表达未绑定、暂定、已固化及版本来源；历史异常有清单；升级不更改已有 Job/Attempt 的路线记录。
- **边界**：仅持久化当前单路线选择所需内容，不提前实现 Route Family fallback 或成本优化路由。

### BL-04B：接入并发安全的项目绑定

- **范围**：项目路线应用服务、`routing.py`、Generation/Batch 创建入口、路由测试。
- 单任务和 Batch 共同使用绑定服务；全局默认仅决定未绑定项目的候选路线。成功固化与任务完成处于受保护的事务边界。
- 已绑定路线停止接单时拒绝新生成，保留在途任务的恢复能力；不静默切换其他路线。
- **验收**：全局默认切换后，同项目仍按绑定执行；两个首任务并发不分裂；批次全部使用正确绑定；停单与提交竞争时结果一致且不遗留冻结。
- **验证**：修复审查路线探针，补数据库并发、停单和 Batch 测试。
- **依赖说明**：计划三的路线 Admin 在此基础上建设，避免再实现另一套启停真相。

### BL-05：补齐 Provider 原始产物清理

- **范围**：产物生命周期模型/迁移、`artifacts.py`、完成服务、`project_cleanup.py` 及测试；按登记和清理两个子 Issue 实施。
- 记录每个 Attempt 的源对象、最终对象及保留状态，覆盖成功、失败、取消、迟到结果和孤立对象。保留窗口和到期清理应配置化并写入 runbook。
- 先明确回调重放需要保留什么，再安排删除；对象清理通过可重试 Outbox，不能以直接删除文件替代生命周期状态。
- **验收**：项目删除后所有到期源对象和最终对象均被清理；保留中的对象有到期时间和后续清理任务；重复删除、删除后宕机重放不误删其他项目对象；未终结 Job 的输入不被提前删除。
- **验证**：修复审查残留探针，并加入失败/迟到/保留期/租约过期测试；“Cleanup 已完成”必须有可核查的对象清单。

### BL-06：完成素材到镜头的用户链路

- **范围**：项目素材 API（仅在缺查询能力时）、项目页、镜头页、前端状态和 E2E。
- 用户可查看已有素材、选择并绑定到镜头、确认当前绑定；刷新可恢复；解绑语义与 Job 快照一致。上传成功和绑定成功分别处理。
- **验收**：通过 UI 上传并选择素材后，要求参考图的模拟 I2V 路线可生成；错误类型/缺失素材在提交前提示；Provider 输入 claim 指向用户所选素材。
- **验证**：新增模拟 I2V E2E，不能只验证 Mock；覆盖刷新、绑定失败、越权素材及更换素材后新旧 Job 的差异。

### BL-07：统一 PATCH 空值语义

- **范围**：Project/Shot 更新 schema、公开 API 契约测试、生成客户端。
- 缺省字段保持原值；可清空的 description 允许 null；name/title/prompt/duration/aspect 等必需字段拒绝 null。
- **验收**：非法 null 返回统一 422 与 request_id，不触发数据库 500；合法清空和空 PATCH 行为明确；OpenAPI 与前端类型一致。
- **验证**：参数化覆盖每个更新字段、缺省/null/有效值；重新导出 OpenAPI 并检查生成结果。

### BL-08：恢复任务轮询和下载

- **范围**：任务详情页、轮询状态模块、前端测试。
- 临时网络错误使用有界退避；401、无权限和不存在等稳定错误停止盲目重试并提示。Job 状态轮询和视频下载可独立恢复。
- **验收**：一次网络错误后会继续查询；终态无多余轮询；下载失败可以重试；离开页面后无悬挂请求、定时器或 Blob URL；返回页面能恢复服务端状态。
- **验证**：使用 fake timers 覆盖异常和卸载；E2E 注入一次轮询失败，最终仍显示成功视频。

### BL-09：业务修复总验收

- 所有 F1–F8 均关联正式 Issue、提交、测试及验收结论；审查探针不能通过修改预期或删除断言来“变绿”。
- 回归关键不变量：一个用户操作只有一个 Job；一个 Job 最多一个最终输出；SETTLE/RELEASE 互斥；账本分录平衡；输入和历史路线不可被改写；清理不越界。
- 输出新的修复验收报告，保留原审查报告作为历史证据。未验证的真实云能力继续明确列为未完成。
- 媒体失败回归覆盖元数据缺失/非法、对象缺失、为空或超限；不再要求识别仅靠解码才能发现的损坏。保留异常时不发布、不结算和正确返还的业务断言。

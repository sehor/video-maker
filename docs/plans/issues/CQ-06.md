# CQ-06：流式 Storage 与有界内存

状态：2026-09-08 本地完成；最终 E2E 两项通过，详见[总验收](../../reports/2026-09-08_代码质量验收.md)。

外层 `ObjectStorage.put(claim, bytes | BinaryIO, mime_type)` 不变。内部先以最多 1MiB
分块复制到自动关闭的磁盘临时文件，超限只多读 1 字节即停止，验证完整流后才尝试目标写入。
Local 继续独占创建，失败只删除自己创建的对象；Remote backend 的 `put` 内容参数从
bytes 改为可 seek 的 BinaryIO，须在返回前消费完成、独占创建、清理自己的失败上传。
适配器在成功/失败返回后关闭临时流，backend 不可持有该句柄。当前只有内存 fake backend，
已同步契约；它为小 fixture 保留 bytes，不代表真实云 SDK 的内存或网络 SLA。
后续 SDK 适配器必须使用流式上传，不得恢复 read-all 或不具备所有权的异常删除。

下载响应按 1MiB 分块，并在响应结束/客户端断开时关闭源。补足 AnyIO 取消作用域屏蔽，
防止 drain 工作线程时重复取消忙循环；取消仍保留原语义且等待底层资源释放。
磁盘暂存增加一次复制，未计算媒体哈希，也未恢复声明大小一致性/解码检查。

## 实测

命令：`rtk proxy uv --cache-dir .tmp-uv-cache run --project apps/api --no-sync python scripts/benchmark_storage.py`。
Windows 10 19045、Python 3.13.7，每个用例独立子进程、惰性生成流，使用 Windows
GetProcessMemoryInfo 的 PeakWorkingSetSize 减执行前 WorkingSetSize；包括分块回读核对。
Remote 使用磁盘 SDK fake，衡量适配器自身内存，不测网络或内存 fake 的对象保留开销。

| 适配器 | 输入 MiB | 空载 MiB | 峰值 MiB | 额外峰值 MiB | 秒 |
|---|---:|---:|---:|---:|---:|
| Local | 64 | 22.367 | 24.438 | 2.070 | 0.129 |
| Local | 512 | 22.223 | 24.297 | 2.074 | 0.985 |
| Remote + 磁盘 fake | 64 | 22.383 | 24.453 | 2.070 | 0.135 |
| Remote + 磁盘 fake | 512 | 22.344 | 24.414 | 2.070 | 1.079 |

输入扩大 8 倍时额外内存保持约 2.07MiB，低于 64MiB 预算。CQ-05 约束单事件循环
最多 4 个在途同步工作；本表为单流测量，不将其冒充并发或真实云测量。

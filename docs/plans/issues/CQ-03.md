# CQ-03：显式执行协作者与统一完成事务

状态：2026-09-08 本地完成；未发布远程 Issue。

`GenerationExecutionService` 不再继承六个服务。Context、Submission、Polling、Callback、
Completion、Settlement 可独立构造，通过参数传入 session 工厂、Storage、registry、
时钟、接收器及协作者。跨协作者调用使用明确对象与公开方法；不提供旧私有方法代理层。

远端与内嵌结果统一进入 `ProviderCompletionService.commit_output`，由同一事务写入
Output、Job/Attempt 终态和结算。Mock 与 `runpod-simulator` 走显式离线 fixture 接收器，
保留损坏 Mock 的 INVALID 诊断记录；Mock 固定 2 秒横屏，模拟器校验请求规格。
其他 Provider 必须使用受控远端对象接收器。MediaFacts 表示已校验声明，不是解码实测。

验证：首轮 30 passed、2 failed（`.test-runs/python-3_9zawdk/python.xml`），失败来自
离线 RunPod 模拟器被误当作真实 Provider；修正明确的离线分支后，polling、provenance、
阶段三模拟验收 12 passed（34.61s，`.test-runs/python-lkh4t8sz/python.xml`）。
首轮通过项包括 webhook 竞争、远端产物、Mock 失败/腐坏、输入快照、Provider 契约。
独立构造和真实 Provider 禁止内嵌绕过 2 passed（0.17s，`.test-runs/python-gy5_bp84/python.xml`）。
未降低原幂等、终态、账本断言；调用入口随组合改造更新。静态检查提交前复核。

IO 仍为同步实现，受控执行由 CQ-05 负责；远程 CI 未运行。

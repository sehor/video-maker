# 91｜外部依赖与许可证

> 新增／升级依赖、模型、custom node 或 Worker 镜像时按需加载。本文是工程治理要求，不代替正式法律意见。

## 1. 采用决策

| 组件 | 决策 | 关键注意 |
|---|---|---|
| Nuxt 4／Nuxt UI | 采用 | 锁定版本 |
| Better Auth | 采用 | Session 与业务用户映射解耦 |
| FastAPI／SQLAlchemy／PostgreSQL | 采用 | 业务唯一真相 |
| Hatchet OSS | 阶段二采用 | 至少一次执行，副作用幂等 |
| R2／Uppy | 采用 | 私有对象，直传 |
| ComfyUI | 阶段三采用 | GPL-3.0；固定 workflow，不开放 UI |
| worker-comfyui | POC 后采用 | AGPL-3.0；视频产物需验证／薄适配 |
| Wan2.2 等模型 | 单独审查 | 锁定具体版本、权重哈希和条款 |
| FFmpeg | 采用 | 记录具体构建和 codec 许可证 |
| New-API | 阶段五可选 | AGPLv3 + Section 7 额外条款 |
| Vast | 阶段五 POC | 不假定兼容 RunPod handler |
| SkyPilot | 条件触发 | 不替代产品 Router |
| Dify／FastGPT／A1111 | 不采用 | 不进入生产依赖 |

## 2. 重点边界

### New-API

作为可替换的独立内部服务，不承载产品账户、项目、账本和路由逻辑。其许可证除 AGPLv3 外还有 Section 7 的界面归属／链接要求；服务拆分不能被当成自动免除义务。fork、修改或网络部署前，需核查源码提供、通知和界面要求。目标商业视频 API 是否支持必须以当前版本集成测试为准。

### worker-comfyui／ComfyUI

锁定 upstream commit，将自有 handler／产物适配与 upstream 修改分开。worker-comfyui 按 AGPL-3.0、ComfyUI 按 GPL-3.0 管理；生产不装 Manager，不运行未批准节点。每个 custom node 单独审查许可证，保留通知、修改说明和可追溯源码版本。

### 模型

每个模型版本登记：来源、权重 SHA-256、许可证、SaaS／商业使用、地区／收入门槛、禁止用途、微调／再分发、输出权利、安全与署名要求、审查日期。“仓库可访问”不等于模型权重可无条件商用。

### FFmpeg

记录发行版或构建参数、实际启用的 codec／library、LGPL／GPL 配置、许可证通知和源代码获取说明；不能只写“FFmpeg 开源”。

## 3. 版本锁定

生产禁止：`latest`、未锁定 branch、运行时自动安装节点、从不受控 URL 下载模型、覆盖旧 workflow／镜像标签。

必须记录：

```text
依赖 lockfile、base image digest、Worker digest
ComfyUI／node commit、模型 SHA-256、workflow hash
SBOM、许可证通知、Benchmark、发布日期和回滚版本
```

建立：

```text
docs/licenses/components.csv
docs/licenses/models.csv
docs/licenses/custom-nodes.csv
```

字段至少含名称、版本、来源、许可证、商业／SaaS 条件、network copyleft、地区／收入限制、修改与通知义务、审查日期和负责人。未更新登记表和许可证扫描的依赖 PR 不得合并。

## 4. Worker 发布门禁

- [ ] 锁定依赖、节点、模型和 workflow；
- [ ] 生成 SBOM 并执行依赖／恶意代码扫描；
- [ ] 完成 custom node 和模型许可证审查；
- [ ] 保存通知、修改说明、镜像 digest 和回滚版本；
- [ ] workflow regression 与 Benchmark smoke 通过；
- [ ] ComfyUI Manager 和任意代码执行入口未进入生产；
- [ ] 用户不能上传 workflow、模型或节点。

正式商用、fork 强 copyleft 组件、改变模型用途或进入新司法辖区前，进行专项许可证与条款审查。

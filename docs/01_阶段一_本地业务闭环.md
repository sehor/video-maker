# 01｜阶段一：本地业务闭环

> 目标：不用真实 GPU，跑通“登录 → 项目 → 镜头 → 上传 → Mock 生成 → 查看结果”。  
> 加载：`00_开发总纲.md` + 本文；涉及字段时再看 `90_核心数据模型与接口契约.md`。

## 1. 交付范围

- Nuxt 用户端、FastAPI API、PostgreSQL 迁移；
- Better Auth Session，FastAPI 通过 JWKS 验证短期 JWT；
- Project、Shot、Asset、Job、Attempt、Output 最小闭环；
- `MockVideoProvider`，可模拟成功、延迟、失败、超时、重复通知和损坏 MP4；
- `LocalObjectStorage` 与 R2 适配接口；
- FastAPI OpenAPI 自动生成 TypeScript Client；
- 结构化日志、权限测试和 Playwright E2E。

本阶段没有真实钱包、Hatchet、GPU、支付和多供应商。

## 2. 用户流程与页面

```text
注册／登录
→ 新建 Project
→ 新建 Shot
→ 上传参考素材
→ 填写提示词、时长、画幅
→ 提交 Mock Job
→ 查看状态
→ 播放／下载测试 MP4
```

最小页面：

```text
/login
/projects
/projects/{id}
/projects/{id}/shots/{shot_id}
/jobs
/jobs/{id}
```

不做营销站、模板市场、团队协作和高级编辑器。

## 3. 关键设计

### 身份

```text
Browser → Better Auth Session → 短期 JWT → FastAPI 验证 JWKS
```

FastAPI 只依赖稳定的 `sub`、issuer、audience 和过期时间；`app_users.auth_subject` 唯一。不要共享 Better Auth Session 表与产品业务表。

### 上传

- Browser 直传对象存储，FastAPI 不转发文件正文；
- 小文件预签名单次 PUT，大文件按阈值启用 Multipart；
- key 使用 UUID，不含用户原文件名；
- 完成上传后校验 MIME、大小、文件头、归属和 SHA-256；
- 对象默认私有，只签发短期下载 URL；
- Worker 将来只接受系统签发的 R2 对象声明，不接受任意公网 URL。

### Provider 接口

```python
class VideoProvider(Protocol):
    async def submit(...): ...
    async def poll(...): ...
    async def cancel(...): ...
```

阶段一由开发执行器调用 Mock；接口边界需保持，阶段二接 Hatchet 时不重写领域逻辑。

### Job 状态

```text
CREATED → QUEUED → RUNNING → SUCCEEDED
                         └→ FAILED_FINAL
CREATED／QUEUED → CANCELLED
```

每次变化写 `job_events`。完整状态机在阶段二加入。

## 4. 最小 API

```text
POST /v1/uploads/prepare
POST /v1/uploads/{id}/complete

POST/GET /v1/projects
GET/PATCH/DELETE /v1/projects/{id}
POST /v1/projects/{id}/assets
POST/GET /v1/projects/{id}/shots
PATCH /v1/shots/{id}

POST /v1/generations
GET  /v1/generations/{id}
GET  /v1/jobs
```

规则：Pydantic 生成 OpenAPI；CI 校验生成的 TS Client；错误统一包含机器码、用户消息和 `request_id`；列表使用稳定分页。

## 5. 工程与安全

本地默认只启动：

```text
web + api + postgres
```

至少提供：

```bash
make dev
make test
make migrate
make generate-client
```

日志关联：`request_id`、`user_id`、`project_id`、`job_id`、`attempt_id`。禁止记录 JWT、Session、密钥、完整签名 URL、文件正文和默认情况下的完整提示词。

权限测试必须证明用户不能读取或绑定他人的 Project、Asset、Job 和 Output。

## 6. 实施顺序

1. Monorepo、Compose、代码规范和迁移；
2. Better Auth 与 FastAPI JWT 验证；
3. 最小数据表和 Project／Shot CRUD；
4. Storage Adapter 与上传；
5. Mock Provider 与 Job／Output；
6. OpenAPI Client；
7. 单元测试、权限测试和 E2E；
8. 用全新数据库执行一遍完整迁移和演示。

## 7. 验收门槛

- [ ] 新用户可建立 Project、Shot 并上传参考素材；
- [ ] Mock 成功、失败、超时、取消和损坏输出均有明确结果；
- [ ] 成功 Job 产生可播放 MP4；
- [ ] 用户不能访问他人对象；
- [ ] 前后端类型由 OpenAPI 保持一致；
- [ ] 全新环境一条命令可启动，测试不依赖 GPU；
- [ ] 代码中不存在 New-API、Vast、SkyPilot 和 2K／4K 路径。

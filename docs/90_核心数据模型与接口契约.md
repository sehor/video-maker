# 90｜核心数据模型与接口契约

> 修改数据库、状态机、账本、Provider 或 Worker 协议时按需加载。数据库保存业务事实；模型、节点和 workflow 先用 Git 中的不可变 manifest 管理。

## 1. 数据归属

| 数据 | 唯一真相 |
|---|---|
| 登录 Session／OAuth | Better Auth |
| 产品用户映射、Project／Shot／Job／Attempt | PostgreSQL |
| 秒数历史 | `ledger_postings`；`wallet_balances` 仅为投影 |
| 工作流执行历史 | Hatchet，同时回写业务状态 |
| 素材与视频 | R2；数据库保存元数据和 object key |
| Worker／workflow／模型版本 | manifest + digest／hash |
| Provider 成本 | Attempt 成本记录 + 外部账单 |

不得读取 New-API、Hatchet 或 Provider 内部表来显示用户余额或业务状态。

### Job 输入快照（BL-02A，兼容阶段）

`0013_job_input_snapshot` 新增 `input_snapshot_json`，无默认值、不回填。SQL NULL 表示
未记录提交时输入；历史终态仍可读取，不能用当前 Shot 或 ShotReference 推测历史输入。
JSON `null`、空对象或未知版本不是有效快照。

版本 1 对应 `app/input_snapshot.py` 的 `JobInputSnapshot`，所有字段必须显式给出：

```json
{
  "version": 1,
  "prompt": "已接受的生成描述",
  "negative_prompt": null,
  "references": [{
    "asset_id": "00000000-0000-0000-0000-000000000001",
    "object_key": "assets/immutable-object.png",
    "reference_role": "FIRST_FRAME"
  }],
  "duration_ms": 2000,
  "resolution": "720P",
  "aspect_ratio": "16:9",
  "mode": "success"
}
```

- `references` 是显式选择的 0 或 1 张图；0 张仅供无参考图的模拟输入。当前真实路线需要
  1 张 `FIRST_FRAME`，选择和路线匹配由 BL-02B 接入；不扩展 STYLE、多图或首尾帧能力。
- 素材 UUID 与不可覆盖的私有对象键均保存，拒绝 URL、绝对路径和非规范路径。
  不对 ShotReference 建外键，解绑不能删除快照。素材归属、可用状态和角色选择在接单时验证。
- `mode` 是现有内部模拟执行模式，不能由公开 HTTP 输入任意控制。时长、分辨率、画幅和
  模式须与 Job 对应列一致；允许的分辨率沿用数据模型，1080P 仍未开放售卖。
- `quote_snapshot_json` 记录计价事实；`input_snapshot_json` 记录执行输入，两者不能互相替代。
- 数据库触发器拒绝任何快照修改，包括从 SQL NULL 补值、清空和替换内容；已有快照的 Job
  也不能把对应生成参数改成不一致值。正常状态变化仍允许。

BL-02B 已让单任务与 Batch 在冻结和 Outbox 的同一事务捕获输入；Project 行锁后重新读取
Shot 与 FIRST_FRAME，避免编辑/提交产生混合版本。Provider 的新 Attempt、恢复和重试只读
Job 快照；旧活动 Job 缺快照时停止推进并留待人工处置，不读取当前 Shot 猜测输入。
兼容迁移默认禁用 `generation_job_input_required` 必填触发器，供切换前的旧代码运行。
BL-02B 部署后暂停接单、排空旧活动任务，再运行受表锁保护的切换脚本启用必填；此后所有新 Job
必须携带快照，旧终态缺失快照的 Job 不能重新激活。历史缺失状态永久保留。
详见 [BL-02A 迁移与切换说明](plans/BL-02A_输入快照契约与迁移.md)。

## 3. 关键约束

BL-03：前端按登录用户 ID/Shot 保存操作 ID、Quote ID、Job ID 与恢复阶段，不保存令牌或生成内容。
同一次操作固定使用 `operation:quote` 与 `operation:generate` 幂等键；请求不明、刷新或同用户
重新登录后使用原 payload 重放，其他用户无法读取该操作。报价过期等明确失败不自动换报价，
只允许用户显式重新生成。API 幂等记录当前无自动清理期限；未来若增加保留期，必须先增加过期
操作的核查流程，不能删除前端记录后直接重新扣费。退出登录保留分用户元数据以供原用户恢复。

- `auth_subject` 唯一；Asset、Shot、Job 的 Project 所有者必须一致；
- `(job_id, attempt_no)` 唯一；Provider Job ID 在对应 Endpoint 内唯一；
- 一个 Job 最多一个最终 Output；Outbox、ledger 和 `(user_id, scope, idempotency_key)`
  幂等键唯一；
- Batch 中的 Quote 必须属于同一用户、Project 和账本单位；Batch 的总冻结交易由全部
  子 Job 共享，非 Batch Job 的冻结交易仍保持唯一；
- 同一 ledger transaction 的分录单位一致且总和为零；
- 秒数和金额使用整数；余额不能只更新投影而不写分录；
- `resolution` 只允许 `720P`、`1080P`，未验证前 Tier 禁用 1080p；
- ledger posting、payment webhook、Job event 和审计记录不硬删除。

阶段二的 PostgreSQL 迁移通过触发器禁止修改或删除 `ledger_postings`，并在事务提交时
校验同一账本交易的分录和为零；Quote 条款不可修改，状态只允许从 `OPEN` 单向进入
`USED` 或 `EXPIRED`。

## 4. 状态机

```text
Job:
CREATED → RESERVED → QUEUED → ROUTING → SUBMITTED → RUNNING
RUNNING／SUBMITTED／ROUTING → CANCEL_REQUESTED
→ POSTPROCESSING → VALIDATING → SUCCEEDED
终止：FAILED_FINAL | CANCELLED | EXPIRED | REJECTED_POLICY

Attempt:
CREATED → SUBMITTING → SUBMITTED → RUNNING → SUCCEEDED
终止：FAILED_RETRYABLE | FAILED_FINAL | CANCELLED | TIMED_OUT
```

使用带预期旧状态的数据库条件更新；只有更新成功者才能在同一事务写入 JobEvent。
Attempt 状态变化也写 JobEvent，并携带 `attempt_id`。回调、轮询和超时竞争时只允许一次
terminal transition；竞争失败者不得写事件、输出或账本动作，Job 成功后迟到的旧 Attempt
不能改写结果。

失败码按组管理：

```text
输入／策略：INVALID_INPUT, POLICY_REJECTED, USER_CANCELLED
能力／条款：UNSUPPORTED_*, LICENSE_BLOCKED, PROVIDER_TERMS_BLOCKED, NO_ROUTE,
          PROVIDER_AUTHENTICATION
临时故障：NETWORK_TIMEOUT, PROVIDER_5XX, PROVIDER_CAPACITY,
          QUEUE_TIMEOUT, WORKER_INTERRUPTED
Worker／媒体：MODEL_LOAD_FAILED, OUT_OF_MEMORY, WORKFLOW_FAILED,
             ASSET_DOWNLOAD_FAILED, OUTPUT_UPLOAD_FAILED,
             OUTPUT_MISSING, OUTPUT_CORRUPTED, OUTPUT_INVALID_MEDIA
内部：LEDGER_ERROR, STATE_CONFLICT, INTERNAL_ERROR
```

只有明确标记为临时故障的错误默认允许自动重试。

### WorkflowStarter 与 Outbox

`POST /v1/generations` 在冻结秒数、创建 Job／Attempt 和写 API 幂等结果的同一个
PostgreSQL 事务中写入 `generation.workflow.start` Outbox 事件。dispatcher 只向
`WorkflowStarter` 提交以下稳定契约，不直接依赖 Hatchet：

```python
class WorkflowStarter(Protocol):
    async def start(self, request: WorkflowStartRequest) -> WorkflowStartResult: ...
```

`WorkflowStartRequest` 包含 `job_id`、稳定键 `generation-job:{job_id}:v1` 和内部 payload。
同一稳定键被重复提交时，Starter 必须返回已接受的同一业务 workflow，不能创建第二个。

阶段二锁定 Hatchet Server `v0.105.2` 与 `hatchet-sdk==1.38.1`。`GenerationWorkflow`
版本 `v1` 以稳定键输入配置 TTL 幂等窗口；Starter 遇到幂等碰撞时返回既有 workflow run ID。
durable parent `Orchestrate` 以递增的 `job:{job_id}:provider-step:{step}:v1` 派生
`GenerationProviderStep` child task，并在非终态结果后使用 Hatchet durable sleep。每个 child
最多领取一次持久 poll 槽；退避、Attempt 截止时间和最大轮询次数均为确定值。poll 槽先写入
PostgreSQL `JobEvent`，因此 child 进程在外部调用前后中断时，恢复执行仍从 Attempt 状态和已领取
次数继续，不重新 submit 同一 Attempt。数据库写入和 Provider 调用只在 child task 中发生，并
继续由 PostgreSQL 条件更新、幂等键和唯一约束保证业务幂等。Hatchet 使用同一 PostgreSQL 实例中
的独立 `hatchet` 数据库保存编排历史，不得读取该数据库覆盖 `video_factory` 中的 Job、Attempt、
账本或 Outbox 状态。

Outbox 状态为 `PENDING → PROCESSING → PUBLISHED`。dispatcher 使用
`FOR UPDATE SKIP LOCKED` 加带 `lock_token` 的条件更新领取租约；发送失败回到 `PENDING`，
进程在发送前或发送后崩溃时保留 `PROCESSING`，租约过期后可由其他实例接管。发送成功但
尚未标记的恢复依赖相同稳定键重放，因此 PostgreSQL 始终保留业务唯一真相。
应用生命周期会持续扫描并优先排空积压；多实例同时运行时仍由数据库租约决定唯一发送者。
`outbox.published`、`outbox.retry_scheduled` 和 `outbox.dispatcher_failed` 使用 Outbox 事件 ID
作为后台链路关联字段，不记录 payload 或用户输入。

Provider 提交后的取消使用独立 `provider.cancel.requested` Outbox。取消 API 在同一事务中把
Job 条件更新为 `CANCEL_REQUESTED`、写 API 幂等结果并插入唯一取消事件；事件通过
`(job_id, event_type)` 和 `attempt:{attempt_id}:cancel:v1` 双重约束绑定当前 Attempt。
Cancel dispatcher 使用与启动 Outbox 相同的 `SKIP LOCKED + lock_token` 租约协议，在
Provider 调用期间定期续租；临时异常写入 `attempt_count`、`next_attempt_at` 和
`last_error` 后重试。Provider 已接受但响应或本地确认丢失时仍用相同稳定键重放。
Provider 返回已取消后调用统一完成路径；若成功、失败或迟到事件先取得终态，取消重放只
完成 Outbox，不改写 Job、Attempt、Output 或账本。最终账本仍由条件更新保证每个 Job 的
Settle／Release 互斥且各最多一次。

## 6. Storage Contract

业务层只依赖统一的 `ObjectStorage`，协议固定为 `put`、`open`、`stat`、`delete`、
`read_claim` 与 `write_claim`。`put` 只接受 write claim，`open` 只接受 read claim；
`stat` 与 `delete` 是 Control Plane 按 object key 使用的内部能力。任何 Provider、领域模型、
应用服务和 Worker DTO 都不得携带或拼接本地 `Path`。

Claim 是 HMAC 签名的短期、最小权限声明，至少绑定版本、操作、object key 和过期时间；
write claim 还绑定 MIME 与最大字节数。Claim 最长有效 15 分钟，过期、签名篡改、读写权限
混用、object key 替换和路径穿越一律拒绝。Claim token 属于敏感凭据，不写日志、不持久化到
业务表，也不作为永久对象地址。

object key 只允许规范化的 POSIX 相对 key。Local adapter 可把 key 映射到开发目录或 Docker
volume；远程 adapter 只通过私有对象客户端操作相同 key。两种 adapter 必须通过同一组
put/open/stat/delete 与 Claim 契约测试，业务层不得根据 adapter 类型分支。

`ProjectAsset` 保存项目私有素材的业务元数据和 object key；`ShotReference` 只连接 Shot 与
ProjectAsset，删除引用不删除素材对象；Shot 本身只保存创作规格。`GenerationOutput` 与素材
生命周期分离，并通过同一 Job 内的复合外键追溯到唯一 Attempt，同时以 object key 和实际大小追溯存储对象。
媒体 sha256 仅为兼容旧记录保留，新媒体存 NULL，不计算或比对；0012 迁移只放宽非空约束。
存在 NULL 时拒绝回退到要求哈希的旧数据库版本，不伪造哈希或删除媒体以完成回退。

## 7. Provider Contract

```python
class VideoProvider(Protocol):
    async def submit(self, request: SubmitRequest) -> SubmitResult: ...
    async def poll(self, attempt: ProviderAttempt) -> PollResult: ...
    async def cancel(self, attempt: ProviderAttempt) -> CancelResult: ...
    async def verify_webhook(
        self, request: WebhookVerificationRequest
    ) -> ProviderEvent: ...
    async def read_cost(self, attempt: ProviderAttempt) -> CostResult | None: ...
```

Provider 只接收不可变 typed DTO，不得持有 ORM Session、业务模型或 Storage 实现。
Provider 原始响应必须在适配器边界映射为统一的 `SubmitResult`、`PollResult`、
`CancelResult`、`ProviderEvent` 和 `CostResult`；数据库状态迁移、对象落盘、媒体校验、
账本结算／返还和商业重试由应用执行层负责。

终态 `PollResult` 可携带规范化的 `ProviderMetrics` 与 `ProviderVersions`，应用执行层再通过
`read_cost` 补齐 `CostResult`。成功结果只有在版本、计时和成本三类快照完整且 workflow 与
Attempt 一致时才允许发布 Output。版本快照包含镜像 digest、Worker version/commit、ComfyUI
version/commit、workflow version/hash 和命名 model SHA-256 集；计时快照使用非负整数毫秒；
金额只使用非负整数最小货币单位和三位币种代码，禁止浮点金额。

快照先写入 `generation_attempts`，`generation_outputs` 再通过同一 Job 内的复合外键指向该
Attempt。任一已写入的版本、计时、成本或规范化 metrics 字段不可修改；poll、webhook、任务
重放和重复完成只复用原快照，不能覆盖历史 Output，也不能再次 settle/release。

阶段三的生成入口先从受控 `ProviderRegistry` 与不可变 `RouteVersion` 选择唯一候选，再把
候选 ID、Provider Endpoint ID、Provider code 和固定 workflow 写入 Job／Attempt。路线版本的
Provider、workflow、分辨率、时长和画幅不可修改；接单开关独立于版本，并在冻结或创建新任务
前检查。关闭后单任务与 Batch 均立即返回 `ROUTE_DISABLED`，已有幂等结果仍可重放。

`SubmitRequest` 必须包含 `job_id`、`attempt_id`、固定 `workflow_id`、系统签发的 input／output／
callback claim 和受控生成规格。input claim 绑定已有私有素材 read 权限，output claim 绑定唯一
对象 write 权限，callback claim 绑定 Job、Attempt、Provider 与 Route version；三者均为最长
15 分钟的签名声明。公共生成请求中的 URL、workflow、model 或版本字段一律拒绝。离线
`runpod-simulator` 可作为受控路线启用；真实 RunPod Provider 与路线仍默认禁用。

`submit` 只有 `ACCEPTED` 与 `UNKNOWN` 两种统一结果。`UNKNOWN` 表示请求可能已被
Provider 接受：Attempt 保持 `SUBMITTING` 并使用稳定键
`attempt:{attempt_id}:submit:v1` 进入 poll／reconcile，任务重放也禁止再次 submit。
poll 或 webhook 必须走同一完成逻辑；Provider event 先按
`(provider_code, external_event_id)` 唯一键进入 inbox，验签失败不得入库；cancel 是
best effort，已提交任务先进入 `CANCEL_REQUESTED`，仅在 Provider 确认终止或最终无有效输出后
进入 `CANCELLED` 并返还；取消竞争中产生的有效输出仍可成功并结算；成本来源明确标记为
`ACTUAL`、`ESTIMATE` 或 `SIMULATED`。`SIMULATED` 只允许受控 Mock／RunPod simulator
写入，模拟执行标成 `ACTUAL` 会按内部契约错误终止且不发布 Output；真实 Provider 不得写入
`SIMULATED`。本阶段不接真实计费 API。

统一失败码由 `FailureCode` 封闭枚举管理。只有 `NETWORK_TIMEOUT`、`PROVIDER_5XX`、
`PROVIDER_CAPACITY`、`QUEUE_TIMEOUT` 和 `WORKER_INTERRUPTED` 默认属于临时错误并可创建
新 Attempt；其他输入、策略、能力、Worker、媒体和内部错误均为确定性错误，不自动重试。
重试预算同时要求：同一 candidate 已创建的 Attempt 少于 2，且整个 Job 已创建的 Attempt
少于 3。达到任一上限即把 Job 终结为 `FAILED_FINAL`，不得再创建 Attempt。

## 8. Worker Contract

输入只允许：

```text
job_id, attempt_id, workflow_id, prompt, negative_prompt?,
系统签发的 reference asset claims, duration_ms, aspect_ratio,
output claim, callback claim
```

输出至少包含：

```text
attempt_id, status, output claim/object_key/媒体元数据 或结构化 error（旧 size_bytes/sha256 可选且不参与一致性验收），
gpu_type, queue/cold-start/runtime/billed-runtime,
Worker/ComfyUI/image/workflow/model 不可变版本与哈希，cost/source
```

Worker 只能执行固定 workflow，无权修改钱包、Job 最终状态、项目权限和永久路由。用户不得传任意 URL、模型、节点、代码或 workflow JSON。
RunPod Adapter 只使用固定的官方 API origin 和 endpoint ID，不接受业务或用户提供的 URL；
Provider 返回按不信任输入严格校验，Attempt ID 或任一发布哈希不一致均拒绝完成。RunPod 当前文档化
webhook 不提供可验证的密码学签名，因此首条路线禁用直收 webhook，以 polling 作为完成来源；
不得把 unsigned callback 接入统一完成函数。

## 9. API 分阶段

```text
阶段一：uploads、projects、assets、shots、generations、jobs
阶段二：generation quote、batches、wallet、ledger、provider webhooks
阶段四：packages、checkout、payment webhooks、admin jobs/routes/
        wallet adjustments/payments/costs/reconciliation
```

FastAPI OpenAPI 是唯一契约，TypeScript Client 自动生成。所有写接口支持业务幂等键；错误返回机器码、用户消息和 `request_id`。

业务修复 BL-06/07：`GET /v1/projects/{id}/assets` 返回本项目 READY 素材，按创建时间/ID
游标分页（每页最多 100）；`PUT /v1/shots/{id}/input` 原子替换唯一 FIRST_FRAME，
`asset_id:null` 明确解绑，图片必须属于同项目、同用户且 READY。引用修改与接单使用同一
Project 行锁，失败保留旧绑定；已经接受的 Job 继续使用自己的快照。
`GET /v1/projects/{id}/generation-options` 仅返回是否需要参考图、时长与分辨率选项，
按项目已绑定路线或未绑定项目的当前默认计算，读取不产生绑定，不暴露 Provider 信息。

Project/Shot PATCH 的省略字段保持原值。name、title、prompt、duration_seconds、
aspect_ratio 明确传 null 返回带 request_id 的 422；description 可以传 null 清空。
空 PATCH 是无变更操作；OpenAPI 将必填业务字段表示为可省略但不可空。

BL-03/08 前端按登录用户和 Shot 持久化操作 ID、Quote ID 与生成幂等键，不保存 token。
响应不明、刷新和重新登录恢复原请求；Quote 明确过期后由用户选择新生成，未知结果不自动
创建新 Quote。当前服务端幂等结果无自动过期策略；将来引入清理时须同步提供结果核对机制。
任务详情临时失败最多退避重试 5 次，稳定错误停止；状态查询和下载分别支持手动重试。
离页取消请求、清除定时器并释放 Blob URL，重新进入以服务端状态为准。

公共 `POST /v1/generations` 只接受 `shot_id` 与 `quote_id`，公共 Batch item 只接受
`quote_id`。Provider、URL、workflow、model 和模拟模式均由内部路由或测试依赖注入，
不得来自普通用户请求。公共 Job／Attempt 响应不返回模拟模式、Provider Job ID、
Provider／GPU／模型／workflow／成本诊断或内部事件；内部失败码统一映射为用户级错误。

受控 Admin Job 诊断使用独立 DTO，并在现有用户认证之上校验管理员 subject 白名单。
Admin、Provider webhook 与内部测试入口不进入公共 OpenAPI；因此自动生成的 TypeScript
Client 只包含普通用户契约。

阶段二 Quote、测试秒数发放、Generation 创建和取消接口接受 `Idempotency-Key` 请求头。
幂等记录按用户和操作隔离，保存规范化请求哈希与业务结果引用，并与业务写入同事务提交；
相同键和相同请求复用原业务结果，相同键但请求哈希不同返回
`409 IDEMPOTENCY_KEY_CONFLICT`。

阶段二单 Job 账本接口为 `POST /v1/quotes`、`POST /v1/generations`、
`GET /v1/wallet` 与 `GET /v1/ledger`。`POST /v1/wallet/test-grants` 只在非生产环境
用于内部验证，不进入公共 OpenAPI，生产环境不暴露。

阶段二 Batch 接口为 `POST /v1/batches` 与 `GET /v1/batches/{batch_id}`。创建请求提交
一组不重复的现有 `quote_id`；服务端先整体验证所有 Quote，再以一个 Batch reserve 交易
冻结总额，并在同一事务创建 Batch、全部 Job／Attempt、Quote Snapshot、Outbox 和 API
幂等结果。任一 Quote 无效或余额不足时整个事务回滚；执行后每个 Job 按自己的冻结额独立
settle 或 release，全部终结后 Batch 聚合为 `SUCCEEDED`、`PARTIAL` 或 `FAILED_FINAL`。

## 10. Workflow manifest

每个不可变版本至少包含：

```text
workflow.json
manifest.yaml          # 输入白名单、时长／画幅／分辨率
nodes.lock             # custom node commit
model-manifest.json    # 模型文件、SHA-256、许可证引用
fixtures/
benchmark-summary.json
```

`manifest.yaml` 同时记录 Worker digest、ComfyUI commit 和输出规范。任何节点、模型、参数或 workflow 变化都创建新版本，禁止覆盖旧版本。

## 结果验收边界（2026-09-06）

RunPod Worker 成功响应 v2 必须提供实际产物的 duration_ms、width、height、fps、codec。控制面校验这些声明与任务策略，以及对象存在、非空和大小上限；不运行 FFmpeg/ffprobe。GenerationOutput.validation_status=VALID 表示元数据/对象基础检查通过，不代表完整解码或视觉质量认证。公开 Output 的 sha256 改为可空，旧值保留、新媒体不生成哈希；账本结算事务不变。

# 90｜核心数据模型与接口契约

> 修改数据库、状态机、账本、Provider 或 Worker 协议时按需加载。数据库保存业务事实；模型、节点和 workflow 先用 Git 中的不可变 manifest 管理。

## 1. 数据归属

| 数据 | 唯一真相 |
|---|---|
| 登录 Session／OAuth | Better Auth |
| 产品用户映射、Project／Shot／Job／Attempt | PostgreSQL |
| 秒数历史 | `ledger_postings`；`wallet_balances` 仅为投影 |
| 工作流执行历史 | Hatchet，同时回写业务状态 |
| 素材与视频 | R2；数据库保存元数据和 object key |
| Worker／workflow／模型版本 | manifest + digest／hash |
| Provider 成本 | Attempt 成本记录 + 外部账单 |

不得读取 New-API、Hatchet 或 Provider 内部表来显示用户余额或业务状态。

## 3. 关键约束

- `auth_subject` 唯一；Asset、Shot、Job 的 Project 所有者必须一致；
- `(job_id, attempt_no)` 唯一；Provider Job ID 在对应 Endpoint 内唯一；
- 一个 Job 最多一个最终 Output；Outbox 和 ledger 幂等键唯一；
- 同一 ledger transaction 的分录单位一致且总和为零；
- 秒数和金额使用整数；余额不能只更新投影而不写分录；
- `resolution` 只允许 `720P`、`1080P`，未验证前 Tier 禁用 1080p；
- ledger posting、payment webhook、Job event 和审计记录不硬删除。

## 4. 状态机

```text
Job:
CREATED → RESERVED → QUEUED → ROUTING → SUBMITTED → RUNNING
→ POSTPROCESSING → VALIDATING → SUCCEEDED
终止：FAILED_FINAL | CANCELLED | EXPIRED | REJECTED_POLICY

Attempt:
CREATED → SUBMITTING → SUBMITTED → RUNNING → SUCCEEDED
终止：FAILED_RETRYABLE | FAILED_FINAL | CANCELLED | TIMED_OUT
```

使用条件更新和事件记录。回调、轮询和超时竞争时只允许一次 terminal transition；Job 成功后迟到的旧 Attempt 不能改写结果。

失败码按组管理：

```text
输入／策略：INVALID_INPUT, POLICY_REJECTED, USER_CANCELLED
能力／条款：UNSUPPORTED_*, LICENSE_BLOCKED, PROVIDER_TERMS_BLOCKED, NO_ROUTE
临时故障：NETWORK_TIMEOUT, PROVIDER_5XX, PROVIDER_CAPACITY,
          QUEUE_TIMEOUT, WORKER_INTERRUPTED
Worker／媒体：MODEL_LOAD_FAILED, OUT_OF_MEMORY, WORKFLOW_FAILED,
             ASSET_DOWNLOAD_FAILED, OUTPUT_UPLOAD_FAILED,
             OUTPUT_MISSING, OUTPUT_CORRUPTED, OUTPUT_INVALID_MEDIA
内部：LEDGER_ERROR, STATE_CONFLICT, INTERNAL_ERROR
```

只有明确标记为临时故障的错误默认允许自动重试。

## 5. 账本不变量

```text
SUM(postings.amount_ms) by transaction + unit = 0
USER_AVAILABLE >= 0

```

## 6. Provider Contract

```python
class VideoProvider(Protocol):
    async def submit(self, attempt, request) -> SubmitResult: ...
    async def poll(self, attempt) -> PollResult: ...
    async def cancel(self, attempt) -> CancelResult: ...
    async def verify_webhook(self, headers, body) -> ProviderEvent: ...
    async def read_cost(self, attempt) -> CostResult | None: ...
```

统一语义：submit 结果未知时可查询／对账；原始状态映射为统一 Attempt 状态和失败码；webhook 与 poll 调用同一完成逻辑；cancel 是 best effort；成本注明实际、账单导入或估算。

## 7. Worker Contract

输入只允许：

```text
job_id, attempt_id, workflow_id, prompt, negative_prompt?,
系统签发的 reference asset claims, duration_ms, aspect_ratio,
output claim, callback claim
```

输出至少包含：

```text
attempt_id, status, output object_key/size/sha256,
gpu_type, queue/cold-start/runtime/billed-runtime,
worker_version, workflow_version, error_code
```

Worker 只能执行固定 workflow，无权修改钱包、Job 最终状态、项目权限和永久路由。用户不得传任意 URL、模型、节点、代码或 workflow JSON。

## 8. API 分阶段

```text
阶段一：uploads、projects、assets、shots、generations、jobs
阶段二：generation quote、batches、wallet、ledger、provider webhooks
阶段四：packages、checkout、payment webhooks、admin jobs/routes/
        wallet adjustments/payments/costs/reconciliation
```

FastAPI OpenAPI 是唯一契约，TypeScript Client 自动生成。所有写接口支持业务幂等键；错误返回机器码、用户消息和 `request_id`。

## 9. Workflow manifest

每个不可变版本至少包含：

```text
workflow.json
manifest.yaml          # 输入白名单、时长／画幅／分辨率
nodes.lock             # custom node commit
model-manifest.json    # 模型文件、SHA-256、许可证引用
fixtures/
benchmark-summary.json
```

`manifest.yaml` 同时记录 Worker digest、ComfyUI commit 和输出规范。任何节点、模型、参数或 workflow 变化都创建新版本，禁止覆盖旧版本。

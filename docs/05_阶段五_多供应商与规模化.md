# 05｜阶段五：多供应商与规模化

> 目标：只有私测数据证明需要时，才增加 Vast、商业 API、1080p 或 SkyPilot。  
> 每个扩展都必须有 POC、Benchmark、许可证审查、灰度和回滚。

## 1. 进入条件与顺序

进入本阶段前，RunPod 720p 路线、账本、Attempt、成本和对账必须稳定。默认顺序：

```text
Vast POC → 第二算力路线 → Route Family／项目亲和性
→ 商业 API → 经验证的 1080p → 成本／容量优化
→ 必要时 SkyPilot 或常驻 Worker Pool
```

不要为了“多云完整”长期维护多个低流量 Provider；每次只增加一个新故障域。

## 2. Vast

先验证 Vast 当前 Serverless／Worker 形态是否适合固定 ComfyUI 视频 workload。可复用模型与 workflow manifest、业务输入／输出协议、媒体校验和 Benchmark 数据集；不能预设 handler、镜像、回调、中断、计费和同名 GPU 性能与 RunPod 相同。

POC 通过后才实现 `VastVideoAdapter`，并独立记录健康、成本和错误映射。

## 3. Route Family 与项目亲和性

Route Family 只包含经过一致性测试、允许互相 fallback 的路线：

```yaml
id: studio_anime_720_v2
primary: wan_i2v_720_runpod_v2
fallbacks: [wan_i2v_720_vast_v2, commercial_anime_720_v1]
```

规则：

- Project 第一次成功后绑定不可变 route version；
- 后续 Shot 优先同 family、workflow family 和参数谱系；
- fallback 必须经过人工一致性测试；
- 不因短期便宜几个百分点就跨族；
- 跨族需用户确认或管理员显式迁移；
- 历史结果永久保留原 route／workflow 版本。

## 4. Hidden Router

继续使用确定性规则，不做强化学习或“大模型调度器”：

```text
Tier／分辨率／时长／画幅／参考类型
→ 许可证／地区／内容／Provider 条款
→ Project family
→ Provider 健康／容量
→ 成本上限
→ 静态优先级和预估成本
```

保存候选集合版本、过滤原因、选中 candidate、预估成本和决策时间，便于审计与回放。

## 5. 商业 API 与 New-API

默认优先专用 `CommercialVideoAdapter`。目标供应商已被 New-API 稳定支持且确能减少适配工作时，才通过 New-API 接入。

无论哪种方式：

- 用户余额只认自有账本；
- Job／Attempt 只认业务数据库；
- 上游 usage 只用于成本和渠道观察；
- Provider 名称和模型名不暴露；
- 内容、地区、商用条款进入 Router；
- submit／poll／webhook／cancel 使用统一 Provider Contract。

New-API 作为可替换的独立内部服务，不承载产品用户、项目、quota 和路由真相。

## 6. 1080p

只有同时满足以下条件才启用：

- 路线真实生成或原生交付 1920×1080／1080×1920；
- 质量、成功率、时延、显存和成本通过固定数据集 Benchmark；
- Tier、价格、时长、画幅和 fallback 已明确；
- UI、API、DB 和 manifest 同步启用；
- 使用与 720p 相同的完整解码校验。

禁止放大 720p 冒充 1080p；2K／4K／AI 超分仍不进入路线图。

## 7. 健康、fallback 与成本

Provider 状态：`HEALTHY`、`DEGRADED`、`DRAINING`、`DISABLED`，依据成功率、队列／总时长 p95、鉴权／容量错误、回调丢失和成本偏差。状态切换需滞后阈值，避免抖动；fallback 仍受最大 Attempt、总时长和成本上限约束。

每个 Provider 独立记录官方 Job／Request ID、计费单位、价格快照、队列／冷启动／运行／计费时间、实际或估算成本、重试成本和最终产物是否采用。每日执行：

```text
Attempt ↔ Provider job/request ↔ Provider bill ↔ 内部成本
```

差异形成 issue，不修改用户历史账本。

## 8. SkyPilot／常驻池

满足任意两项再评估：三家以上 GPU 云、Serverless 长期明显更贵、任务持续占满 GPU、需要统一 autostop／部署／故障转移、同一 workload 频繁跨云。

SkyPilot 只管理 workload 部署位置，不决定 Tier、内容策略、许可证、项目亲和性和用户余额；产品 Router 仍是决策层。

## 9. 新路线发布门槛

- [ ] POC、Provider Contract Test 和固定数据集 Benchmark 通过；
- [ ] 商用、地区、内容和许可证条款已登记；
- [ ] Worker、模型、workflow 和成本可追溯；
- [ ] 失败、取消、回调和对账语义明确；
- [ ] 有 kill switch、回滚和成本上限；
- [ ] 与现有项目的一致性已评估；
- [ ] 灰度后才加入正式 Route Family。

仍不开发：用户可见模型选择、自动安装节点／模型、用户 LoRA／checkpoint／workflow、模型市场、强化学习调度、自研通用 GPU 云平台、2K／4K／8K和 AI 超分。

# 04｜阶段四：私测上线

> 目标：把稳定的单一 720p 路线包装成可邀请、可收款、可运营、可追责的私测产品。  
> 前置：阶段三通过固定数据集 Benchmark 和小流量灰度。

## 1. 交付范围

- Project／Shot／Batch／Job 完整产品 UI；
- 套餐、Checkout、支付 webhook 和秒数发放；
- 最小内容策略与人工复核；
- 产品 Admin；
- 监控、告警、备份、Runbook 和每日对账；
- staging／production 部署；
- 隐私、用户条款和许可证发布检查。

私测可暂时只用 RunPod。稳定性不足时停止接单，不为“多云”引入未验证故障域。

## 2. 产品 UI

页面至少有：

```text
/projects、/projects/{id}、/shots/{id}
/batches/{id}、/jobs、/jobs/{id}
/pricing、/wallet、/ledger、/checkout、/account
```

用户只选择参考素材、提示词、时长、画幅、质量档和 variant 数量，不看到模型、workflow、GPU、Provider 或内部错误栈。

Batch 提交前显示总镜头、variant、秒数和余额；先 Quote 后确认；逐 Job 展示状态，只下载成功产物。

## 3. 套餐与支付

套餐指定价格、币种、发放的账本单位和有效期。流程：

```text
payment_order → checkout → 验签 webhook
→ 校验金额／币种／商品／环境 → 标记 paid
→ 幂等 ledger grant
```

浏览器 success page 不能入账；webhook event 和 order ID 唯一；重放不重复发放；退款用反向账本交易，不删除历史；支付平台和 New-API 均不维护真实秒数余额。

## 4. 内容策略

承诺是“减少合法虚构创作的无意义误杀”，不是无审核。MVP 分类：

```text
ALLOW / REVIEW_REQUIRED / BLOCK
```

提交前检查文本和元数据；`REVIEW_REQUIRED` 进入人工队列；`BLOCK` 不扣费；输出发布前做最小结果检查。至少阻止未成年人性内容、非自愿私密内容、可识别真人性化深伪、身份欺诈、违法剥削，以及会导致算力／支付账户封禁的内容。

内部策略码不得绑定某一家商业 API taxonomy。

## 5. Admin

必要能力：

- 查看 Job 的全部 Attempt、事件、Worker 和 workflow 版本；
- enable／disable route、暂停新任务；
- 受控重试和异常冻结释放；
- 通过双分录调整余额；
- 处理人工复核；
- 查看支付、成本、对账和审计。

高风险操作必须二次确认、填写理由并写审计。禁止直接改余额、伪造成功或覆盖历史 workflow。

## 6. 监控与对账

关联字段：`request_id`、`job_id`、`attempt_id`、Provider Job ID、Worker／workflow、payment order。

最小指标：任务成功率和时延、Provider 错误、Outbox 堆积、Hatchet worker、R2 失败、重复回调、账本差异、成本／成功输出秒、人工审核积压。Prometheus 只使用 Provider、route、workflow、tier、resolution 等低基数标签。

每日对账：

```text
ledger postings ↔ balance projection ↔ Job reserve/settle/release
Attempt ↔ RunPod job ↔ Provider bill ↔ 内部成本
payment order ↔ webhook ↔ provider settlement ↔ ledger grant
```

差异生成 issue，不静默改写历史。

## 7. 部署与 CI/CD

生产先用 Docker Compose：

```text
traefik、web、api、hatchet-worker、outbox-dispatcher、postgres、hatchet、
otel-collector、prometheus、grafana
```

local／staging／production 的数据库、R2 空间、Auth、支付、RunPod、callback、Tier 和告警全部隔离。数据库每日备份并定期恢复演练；迁移先 staging，破坏性变更采用 expand／migrate／contract；ledger、payment 和 Job event 不硬删除。

PR 必跑 lint、typecheck、单元／迁移／OpenAPI／Provider Contract 测试、依赖／许可证／密钥扫描。控制面与 Worker 分开发布；新 Worker／workflow 先 staging 和灰度，再由路由后台启用。

## 8. 上线演练与验收

至少演练 RunPod 故障、R2 不可写、Hatchet worker 重启、支付 webhook 延迟／重复、数据库恢复、Route 停单和 callback secret 轮换。

- [ ] 用户流程不暴露模型、GPU、Provider 和 workflow；
- [ ] 支付只以验签 webhook 入账，重放不重复发放；
- [ ] 支付、账本、Job 和成本对账可重复运行；
- [ ] 系统失败只返还一次；
- [ ] 人工复核和 BLOCK 流程可用；
- [ ] Route 可立即停止新任务；
- [ ] 成功率、时延、成本、Outbox 和账本异常有告警；
- [ ] 环境完全隔离并完成备份恢复；
- [ ] 发布条款和许可证已复核；
- [ ] 私测只销售已稳定开放的 720p 能力；
- [ ] 2K／4K／超分在 UI、API、DB 和 manifest 中均不存在。

## 9. 不做

Vast、第三家算力云、自动竞价、SkyPilot、用户模型／LoRA／workflow、公共模型商城、公开大规模发布和未验证 1080p。

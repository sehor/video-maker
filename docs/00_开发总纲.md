# 00｜AI 视频镜头工厂开发总纲

> 版本：v2.0｜日期：2026-08-17｜开发时与当前阶段文档一起加载

## 1. 产品与边界

用户购买“质量档 + 可生成视频秒数”，不看到模型、工作流、GPU 或供应商。核心能力只有：Project／Shot／Batch、项目一致性、秒数钱包、可靠长任务、隐藏路由和视频 SaaS 前端。

全系统只允许：

```text
720p：1280×720 / 720×1280
1080p：1920×1080 / 1080×1920
```

第一条真实路线只做 720p。1080p 必须有经过验证的真实路线后才启用。明确不做：图片产品、2K／4K／8K、AI 超分、用户模型／LoRA／节点／workflow、ComfyUI 画布、模型市场、Agent、RAG、Dify、FastGPT、A1111，以及 MVP 阶段的 Kubernetes 和自研 GPU 调度平台。

## 2. MVP 架构

```text
Nuxt 4 + Better Auth
        │ 短期 JWT
        ▼
FastAPI Control Plane
  Project / Shot / Batch / Quote / Job / Ledger / Router / Admin
        ├─ PostgreSQL：业务唯一真相
        ├─ LocalStorage：开发阶段素材与结果（本地目录／Docker volume）
        └─ Hatchet：持久编排
               ├─ MockVideoProvider（阶段一、二）
               └─ RunPod Adapter（阶段三）
                         ▼
          worker-comfyui 基础 + 固定 ComfyUI workflow + FFmpeg
```

Vast、New-API、商业 API 和 SkyPilot 不进入首版主链路。

## 3. 组件职责

| 组件 | 负责 | 不负责 |
|---|---|---|
| Nuxt／Better Auth | 页面、Session、短期 JWT | 账本和长任务状态 |
| FastAPI | 权限、项目、报价、任务、路由、支付、Admin | GPU 推理 |
| PostgreSQL | Job／Attempt、账本、路由版本、支付、审计 | 工作流执行 |
| Hatchet | 持久等待、重试、并发、恢复 | 业务状态唯一真相 |
| Worker | 通过 Storage 接口读取素材、写入产物、执行固定 workflow、上报指标 | 用户、钱包、路由和商业重试 |
| LocalStorage | 开发阶段保存私有素材与结果；使用本地目录或 Docker volume | 业务元数据、生产对象存储能力 |

FastAPI OpenAPI 是接口唯一来源，TypeScript Client 自动生成。

## 4. 技术栈

```text
Web/UI        Nuxt 4 + Nuxt UI + TypeScript
Auth          Better Auth JWT/JWKS
API/ORM       FastAPI + SQLAlchemy 2 + Alembic
Database      PostgreSQL
Workflow      Hatchet OSS
Storage       FastAPI multipart 上传 + LocalStorage（本地目录／Docker volume）
Worker        RunPod worker-comfyui 基础 + ComfyUI
Media         FFmpeg / ffprobe
Test          Pytest + Vitest + Playwright
Proxy         Traefik（staging/production）
```

开发阶段由 FastAPI 接收 `multipart/form-data`，校验类型、大小和权限后写入
LocalStorage；前端使用原生 `FormData`，不引入 Uppy、S3 API、预签名上传或
Multipart Upload。业务代码只依赖统一 Storage 接口，不直接拼接本地路径。
上线前再根据阶段四的容量、带宽和部署环境选择对象存储，并新增对应适配器。

## 5. 全局规则

1. **Job 与 Attempt 分离。** 用户只为 Job 结算一次；供应商重试产生多个 Attempt。
2. **PostgreSQL 是业务真相。** Hatchet、New-API、Provider 日志和指标系统不能替代它。
3. **双分录秒数账本。** 所有冻结、结算、返还和人工调整均有不可变分录。
4. **至少一次执行。** Outbox、回调、轮询和任务重放均靠幂等键、唯一约束和条件更新防重。
5. **路由版本不可变。** Project 绑定具体版本；后台修改不改写历史。
6. **用户输入不进入任意执行。** 禁止任意 workflow、代码、模型路径、节点和公网 URL。
7. **对象默认私有。** 只用短期签名或系统声明访问。
8. **不使用 `latest`。** 镜像、依赖、节点、模型和 workflow 均锁定版本或哈希。
9. **先单路线后多供应商。** 新路线必须 POC、Benchmark、许可证审查和灰度。
10. **能力真实存在才售卖。** 不预留虚假的 1080p、2K 或 4K 路径。

## 6. 精简仓库

```text
video-factory/
├─ apps/web                 # Nuxt
├─ apps/api                 # FastAPI + Hatchet workers
├─ packages/api-client      # OpenAPI 自动生成
├─ workers/runpod-comfyui   # 阶段三加入
├─ workflows/manifests      # 不可变 manifest
├─ infra/{compose,traefik,observability}
├─ scripts/{benchmark,reconcile,release-worker}
├─ docs/{adr,licenses,runbooks}
└─ tests/{fixtures,e2e}
```

不 fork ComfyUI、Hatchet、New-API 或大模型权重进主仓库。确需修改强 copyleft 组件时，补丁、对应源码和通知单独管理。

## 7. 阶段顺序

```text
1 本地业务闭环
→ 2 秒数账本与可靠任务
→ 3 RunPod 第一条真实 720p 路线
→ 4 私测上线
→ 5 多供应商与规模化
```

禁止跳过阶段二直接接真实 GPU。

## 8. 公开收费前总验收

- 并发提交不超扣，重放不重复结算或返还；
- API、Hatchet worker 或 Provider 回调中断后可恢复；
- 每个输出可追溯到 Attempt、Worker、workflow 和模型哈希；
- 用户看不到模型、GPU、Provider 和 workflow；
- UI、API、DB 和 manifest 仅允许已验证的 720p／1080p；
- ComfyUI 不暴露公网，用户不能提交任意执行内容；
- 生产与测试环境的密钥、数据库和对象空间完全隔离；
- 依赖、模型和节点的商用条件有登记；
- Route 可立即停止接单，账本与供应商成本可对账。
